# Ka7

Réécriture de `../youtubeDl/` en Flutter : une seule app (Linux, macOS, Windows, Android, iOS) qui transforme des liens YouTube en fichiers MP3 / MP4 propres. Pas de version web. Pas de Rust.

## Documents (fichiers locaux, ne jamais les publier en ligne)

- `../ka7-reecriture-flutter.html` : technologies, architecture, moteurs, fonctionnalités en flux (0 à 5), étapes, risques, couleurs, nom, identité. Référence pour ce qui doit être construit.
- `../ka7-maquette.html` : maquette cliquable (bureau et téléphone, clair et sombre, FR / EN). Référence de parcours et de mise en page, pas de rendu au pixel.
- `../ka7-brand/` : logo, icône (SVG, PNG 1024 à 48), silhouette monochrome.
- `PRODUCT.md`, `DESIGN.md` : contexte produit et règles de design pour les skills d'interface.

## Outils : toujours via fvm

Flutter n'est pas installé globalement. Version fixée par `.fvmrc` (canal `stable`).

- `fvm flutter …`, `fvm dart …` : jamais `flutter` ni `dart` seuls.
- `fvm dart pub get` à la racine : installe tout le workspace.
- `fvm flutter run -d linux` depuis `app/` pour lancer l'app.

## Structure (pub workspace)

- `pubspec.yaml` (racine) : workspace, membres `app`, `packages/ka7_core`, `packages/ka7_engine_ytdlp`, `packages/ka7_engine_explode`, `packages/ka7_store`, `cli`.
- `packages/ka7_core/` : cœur en Dart pur, sans Flutter (liens — une ligne faite seulement de mots libres (message collé, titre) donne une seule `InvalidEntry` « pas un lien » (`freeText`), jamais une recherche ; une `SearchEntry` ne vient que du mode « Recherche YouTube » ou de « Nouvelle recherche » de l'aperçu, `searchLimit` = 20 résultats —, sondes (`Probe.isSearch` : résultats décochés dans l'aperçu), noms de fichiers (`FolderLayout.playlist` ou `.artist` = dossier de la chaîne YouTube, repli sur la playlist si inconnue), file de téléchargement `DownloadQueue`, événements `JobEvent`, bilan, `failed.txt`). Partagé par l'app et le CLI.
- `packages/ka7_engine_ytdlp/` : moteur bureau. `EngineBinaries` (implémente `EngineSetup`) trouve yt-dlp et ffmpeg (copies de l'app d'abord, puis `PATH`) et installe les binaires officiels : yt-dlp autonome, ffmpeg en build LGPL de BtbN (vérifié : pas de `--enable-gpl`). `DailyUpdate` (décorateur d'`EngineSetup`) lance `EngineBinaries.updateYtDlp` (`yt-dlp -U`, seulement sur la copie de l'app, jamais celle du `PATH`) au plus une fois par jour, au `check()` du démarrage, délai max 1 min ; date du dernier succès dans le réglage `ytdlp.updated` (branché dans `app/lib/main.dart`). Le CLI ne met rien à jour. `YtDlpExtractor` (lecture, lanceur `RunProcess` injecté) et `YtDlpDownloader` (téléchargement, conversion MP3 / MP4, tags et pochette via ffmpeg, progression, annulation ; lanceur `StartProcess` injecté). Les fixtures de `test/fixtures/` sont de vraies sorties de yt-dlp 2026.10.26, raccourcies.
- `packages/ka7_engine_explode/` : moteur en Dart pur sur youtube_explode_dart, seul moteur d'iOS et moteur actuel d'Android. Logique dans `ExplodeEngine` (testée avec `FakeSource`), réseau dans l'adaptateur mince `YoutubeExplodeSource`. Fait M4A (audio d'origine) et MP4 muxé (360p max) ; MP3 refusé (`formatUnsupported`) faute de ffmpeg. Essai réel : `cd packages/ka7_engine_explode && fvm dart run tool/live_check.dart <dossier>`. État au 2026-10-30 : vidéo seule OK, playlists et chaînes vides (youtube_explode 3.1.0 cassé, dépôt amont inactif depuis mai 2026) ; le moteur les signale en échec au lieu de les rendre vides.
- `packages/ka7_store/` : mémoire locale drift (SQLite) : archive « déjà téléchargé », historique, réglages (clé → valeur), file en cours (`keepPending` / `dropPending` / `pending`, table `pending_downloads`). L'historique garde l'id de playlist (`HistoryItem.playlistId`, null pour une vidéo seule ou une chaîne). « Déjà là » vérifié sur disque : `VerifiedArchive` (archive + `lastPath`, le fichier du dernier téléchargement réussi ; s'il manque, `unarchive` pour ce format, l'historique reste ; sans chemin connu, l'archive fait foi). Branché via `Ka7App.fileExists` (bureau : `File.exists` ; Android : `AndroidMediaStore.existsFor`, méthode `exists` de `MediaStoreChannel.kt`, qui cherche `Music/Ka7/…` dans MediaStore, ou le fichier resté dans le dossier de l'app) et dans le CLI. Abonnements : `follow` / `unfollow` / `subscriptions` (table `subscriptions`, `link` relisible par `parseEntry`). Schéma v9 (listes de lecture, listes-dossiers, ordre des listes) ; `test/fixtures/schema_v1.sql` à `schema_v8.sql` sont de vraies bases pour tester les migrations. Code généré `lib/src/database.g.dart` : après toute modification des tables, `cd packages/ka7_store && fvm dart run build_runner build`, puis augmenter `schemaVersion` et écrire la migration.
- `cli/` : commande `ka7` (`ka7 links.txt [--format mp3|mp4] [--out dossier] [--jobs 2] [--lang fr|en] [--yes]`, `ka7 retry`). Les mots libres y sont signalés « not a link », comme dans l'app. Pose des questions o/N (chaîne : tout télécharger ? vidéo ouverte depuis une playlist : toute la playlist ?) ; `--yes` répond oui, sans terminal la réponse est non. Barre de progression seulement si la sortie est un terminal (`stdioType`, pas `hasTerminal`, faux sans largeur de fenêtre). Logique testable dans `lib/src/ka7_cli.dart`, branchement réel dans `bin/ka7.dart`. Base partagée avec l'app : `~/.local/share/mg.rakoto.ka7/ka7.sqlite` (Linux). Binaire : `cd cli && fvm dart build cli` (embarque `libsqlite3.so`). Tester Ctrl+C sur le binaire, pas via `fvm dart run`, qui coupe la sortie.
- `app/` : app Flutter, sans logique métier testable sans Flutter (elle va dans `ka7_core`). `Ka7App` (réglages, thème, langue) → `EngineGate` (flux 0 : outils manquants, installation) → `Ka7Shell` (barre latérale, qui défile quand elle est plus haute que la fenêtre, téléphone en paysage par exemple (KA-4) ; ou onglets sous 720 px ; Ajouter, File, Bibliothèque, Réglages ; tient les files en cours et écrit l'historique). Chaque titre mis en file est gardé dans le store jusqu'à sa fin (réussi, ignoré, échoué, annulé par l'utilisateur) ; fermeture ou plantage le laissent, et au lancement suivant l'app s'ouvre sur File avec la carte « File interrompue » : Reprendre (même format, même dossier) ou Abandonner (annulés dans l'historique). Composants communs dans `lib/widgets/` (`Ka7Page`, `StatusPill`, `Ka7Wordmark`, `Ka7Splash` : écran d'attente au chargement des réglages et pendant `EngineGate` (« Préparation du moteur… »), bobines qui tournent en boucle (`Ka7Logo(loading: true)`) — dans les tests, `pump()` et non `pumpAndSettle()` tant qu'il est affiché ; `Ka7Logo` : cassette de `../ka7-brand/ka7-mark.svg` dessinée en `CustomPainter` aux couleurs du thème, dans la barre latérale et au démarrage). Premier lancement : `OnboardingScreen` (d'abord langue et thème, appliqués tout de suite et enregistrés dans `AppSettings`, puis 4 pages avec points animés, logo aux bobines qui tournent, « Précédent » / « Passer » ; points selon `canDrop` / `canShare` ; animations coupées si le système le demande), avant `EngineGate` ; réglage `onboarding.done`. Les tests d'`app_test.dart` le posent dans `setUp` ; le retirer pour tester la présentation.
- À venir, chacun avec sa première tranche testée : `packages/ka7_engine_explode`.
- Identifiant d'app : `mg.rakoto.ka7` (définitif).
- Formats : `MediaFormat.mp3`, `m4a` (audio d'origine, même dossier que MP3), `mp4`. Bureau et Android proposent MP3, M4A et MP4 ; iOS M4A/MP4 (`Ka7App.formats`, posé dans `main.dart`).
- `app/lib/main.dart` choisit par plateforme : bureau (yt-dlp, `EngineGate`, dossiers par défaut `<Musique XDG>/Ka7` et `<Vidéos XDG>/Ka7` (`ka7Folder`, `platform/user_folders.dart`), comme Music/Ka7 et Movies/Ka7 sur le téléphone ; un dossier choisi dans Réglages prime, `xdg-open`) ou mobile (`ExplodeEngine`, pas d'`EngineGate`, dossiers `Android/data/mg.rakoto.ka7/files/{Music,Movies}` ou `Documents` iOS visibles dans l'app Fichiers, pas d'ouverture de dossier).
- Android : moteur yt-dlp embarqué (youtubedl-android 0.18.1, `android/app/src/main/kotlin/mg/rakoto/ka7/YtDlpChannel.kt`), vu côté Dart comme un processus (`app/lib/platform/android_ytdlp.dart`), donc `YtDlpExtractor` et `YtDlpDownloader` servent tels quels. `AndroidEngineSetup` décompresse le moteur à chaque lancement ; yt-dlp est mis à jour au plus une fois par jour par le même `DailyUpdate` que le bureau (`updateYtDlp`, réglage `ytdlp.updated`, helper `_daily` dans `main.dart`) — le yt-dlp embarqué de nov. 2025 ne lit plus YouTube. Secours automatique : `FallbackExtractor` / `FallbackDownloader` (`ka7_core`) essaient yt-dlp puis youtube_explode, sauf vidéo privée ou indisponible.
- ffmpeg Android (ticket 001) : `tool/android/build_ffmpeg.sh` compile ffmpeg 8.1.3 + LAME 3.100 (sources vérifiées par SHA-256) avec le NDK, pour les 3 ABI, en pages de 16 Ko, LGPL : `libffmpeg.so` et `libffprobe.so` autonomes (seulement libc, libm, libz du système) et un `libffmpeg.zip.so` presque vide, dans `app/android/app/src/main/jniLibs/<abi>/` (ignoré par git), qui remplacent ceux de youtubedl-android (`pickFirsts`, `build.gradle.kts`). youtubedl-android lance `libffmpeg.so` (`--ffmpeg-location`) ; yt-dlp trouve `libffprobe.so` à côté. Lire tout, écrire peu : décodeurs audio courants, images (webp, png, jpeg), conteneurs courants, tous les parsers et bsf ; encodeurs seulement `libmp3lame`, `aac`, `mjpeg`, `png` (jamais de vidéo : un MP4 est assemblé sans réencoder) ; pas de réseau (à ajouter si une autre source l'exige, ticket 004). `KA7_ABIS=x86_64` pour une seule ABI. Lancé par `tool/package_android.sh` s'il manque. Formats vérifiés : voir le ticket 001. L'émulateur `Android_17.0_API_24` est en 16 Ko.
- Qualité (ticket 002) : `Quality` (`ka7_core/lib/src/quality.dart` : `AudioQuality` 128/192/320 kbit/s pour le MP3, `VideoQuality` 480p/720p/1080p/max pour le MP4 ; `Quality.standard` = 192 + 1080p) dans `DownloadRequest` et `DownloadQueue`. yt-dlp : `--audio-quality <kbps>K`, `-f` limité en hauteur avec repli si rien ne rentre (vérifié sur vrai yt-dlp 2026-11-05). M4A : pas de choix (son d'origine). youtube_explode l'ignore (360p muxé). Aperçu : petit menu « 192 kbit/s ▾ » / « 1080p ▾ » à côté du total (`_QualityMenu`), départ = défaut des Réglages (`quality.audio`, `quality.video`, carte Téléchargements). File : une file = format + dossier + qualité ; `pending_downloads` garde la qualité (schéma v6, colonnes `audio_quality`, `video_quality`, nulles avant = défaut) et « Reprendre » relance dans la même. - Lecteur (ticket 003, fait, version 0.4.0) : media_kit (libmpv, audio et vidéo, bureau et Android ; `media_kit_libs_video`). Linux : Ka7 fournit **sa propre** libmpv, compilée LGPL (celle d'Ubuntu est GPL : `--enable-gpl` dans libavcodec, option `gpl` dans libmpv ; Ka7 ne distribue que du LGPL ou plus permissif). `tool/linux/build_libmpv.sh` (dans l'image Ubuntu 22.04, lancé par `package_linux.sh` s'il manque ; tampon de versions dans `app/linux/libmpv/VERSIONS`, ignoré par git) : FFmpeg 8.1.3 (même archive et SHA-256 qu'Android, `--disable-autodetect`, sans `--enable-gpl` ni `nonfree`, lecture seule : sans encodeurs ni muxers), dav1d 1.5.3 (AV1, BSD, lié dans FFmpeg : les versions d'Ubuntu diffèrent), libplacebo 7.360.1 (OpenGL seul), mpv 0.41.0 (`-Dgpl=false`, `plain-gl`, pulse, alsa), libass d'Ubuntu 22.04 copiée (ISC ; GTK ne l'apporte pas, sans elle Ka7 ne démarrait pas du tout). mpv, dav1d et libplacebo épinglés par commit (pas par l'objet étiquette : le script vérifie `rev-parse HEAD`), sources gardées dans `~/.cache/ka7-tools/sources` (commit seul, sous-modules sans historique : le Vulkan-Headers complet prenait 15 min). Vérification sur un vieux Linux, conteneur propre avec écran virtuel : `tool/linux/check_old_linux.sh dist/Ka7-<v>-x86_64.AppImage dist/ka7_<v>_amd64.deb` (AppImage et `.deb` debout 15 s, `ka7 --help` répond ; `KA7_OLD_LINUX=debian:12` pour une autre base). `.rpm` : `rpmbuild` dans la même image, sans rien toucher aux fichiers (pas de strip, pas de paquet debug, `AutoReqProv: no` : sinon les bibliothèques fournies seraient demandées au système), dépendances aux noms Fedora écrites à la main (dont `libglvnd-gles` : sans OpenGL ES, Flutter abandonne au démarrage, « Couldn't open libGLESv2.so.2 », vu sur Fedora 43), reproductible (`SOURCE_DATE_EPOCH`, hôte fixe, xz) ; vérifié par `tool/linux/check_fedora.sh dist/ka7-<v>-1.x86_64.rpm` (Fedora propre : `dnf install`, bibliothèques complètes, lecture des fichiers d'essai, app debout 15 s avec la libmpv de Ka7, `ka7 --help`, menu et icônes, `dnf remove` propre ; `KA7_FEDORA=fedora:43` pour la plus ancienne suivie). À lancer avant chaque release. Icônes et `.desktop` dans `packaging/linux/` (copies de `../ka7-brand/`). Version lue dans `app/pubspec.yaml`.

## Git

- Avant tout changement : `git switch main && git pull`, puis une nouvelle branche pour ce changement.
- Commit et push **seulement quand l'utilisateur le demande**, jamais de sa propre initiative, même quand le travail est fini et vérifié : le laisser non commité et le dire.
- Pull request vers `main` (`gh pr create`) et fusion seulement quand l'utilisateur le demande, après sa validation.
- Fusion = rebaser **la branche** sur `main`, puis avancer `main` jusqu'à elle : les commits gardent leurs identifiants, Git et GitHub voient la branche fusionnée et la pull request passe « Merged » d'elle-même. Pas le bouton « Rebase and merge » de GitHub (`gh pr merge --rebase`) : il recopie les commits sous de nouveaux identifiants et la branche paraît non fusionnée.
  ```bash
  git switch <branche> && git fetch origin && git rebase origin/main
  git push --force-with-lease            # tests à relancer si le rebase a changé quelque chose
  git switch main && git pull --ff-only && git merge --ff-only <branche>
  git push origin main
  ```
