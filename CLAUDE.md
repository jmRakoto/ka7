# Ka7

Réécriture de `../youtubeDl/` en Flutter : une seule app (Linux, macOS, Windows, Android, iOS) qui transforme des liens YouTube en fichiers MP3 / MP4 propres. Pas de version web. Pas de Rust.

## Documents (fichiers locaux, ne jamais les publier en ligne)

- `../ka7-reecriture-flutter.html` : technologies, architecture, moteurs, fonctionnalités en flux (0 à 5), étapes, risques, couleurs, nom, identité. Référence pour ce qui doit être construit.
- `../ka7-maquette.html` : maquette cliquable (bureau et téléphone, clair et sombre, FR / EN). Référence de parcours et de mise en page, pas de rendu au pixel.
- `../ka7-brand/` : logo, icône (SVG, PNG 1024 à 48), silhouette monochrome.
- `PRODUCT.md`, `DESIGN.md` : contexte produit et règles de design pour les skills d'interface.

## Outils : toujours via fvm

Flutter n'est pas installé globalement. Version fixée par `.fvmrc` (canal `stable`).

- `fvm flutter …`, `fvm dart …` : jamais `flutter` ni `dart` seuls.
- `fvm dart pub get` à la racine : installe tout le workspace.
- `fvm flutter run -d linux` depuis `app/` pour lancer l'app.

## Structure (pub workspace)

- `pubspec.yaml` (racine) : workspace, membres `app`, `packages/ka7_core`, `packages/ka7_engine_ytdlp`, `packages/ka7_engine_explode`, `packages/ka7_store`, `cli`.
- `packages/ka7_core/` : cœur en Dart pur, sans Flutter (liens — une ligne faite seulement de mots libres (message collé, titre) donne une seule `InvalidEntry` « pas un lien » (`freeText`), jamais une recherche ; une `SearchEntry` ne vient que du mode « Recherche YouTube » ou de « Nouvelle recherche » de l'aperçu, `searchLimit` = 20 résultats —, sondes (`Probe.isSearch` : résultats décochés dans l'aperçu), noms de fichiers (`FolderLayout.playlist` ou `.artist` = dossier de la chaîne YouTube, repli sur la playlist si inconnue), file de téléchargement `DownloadQueue`, événements `JobEvent`, bilan, `failed.txt`). Partagé par l'app et le CLI.
- `packages/ka7_engine_ytdlp/` : moteur bureau. `EngineBinaries` (implémente `EngineSetup`) trouve yt-dlp et ffmpeg (copies de l'app d'abord, puis `PATH`) et installe les binaires officiels : yt-dlp autonome, ffmpeg en build LGPL de BtbN (vérifié : pas de `--enable-gpl`). `DailyUpdate` (décorateur d'`EngineSetup`) lance `EngineBinaries.updateYtDlp` (`yt-dlp -U`, seulement sur la copie de l'app, jamais celle du `PATH`) au plus une fois par jour, au `check()` du démarrage, délai max 1 min ; date du dernier succès dans le réglage `ytdlp.updated` (branché dans `app/lib/main.dart`). Le CLI ne met rien à jour. `YtDlpExtractor` (lecture, lanceur `RunProcess` injecté) et `YtDlpDownloader` (téléchargement, conversion MP3 / MP4, tags et pochette via ffmpeg, progression, annulation ; lanceur `StartProcess` injecté). Les fixtures de `test/fixtures/` sont de vraies sorties de yt-dlp 2026.10.26, raccourcies.
- `packages/ka7_engine_explode/` : moteur en Dart pur sur youtube_explode_dart, seul moteur d'iOS et moteur actuel d'Android. Logique dans `ExplodeEngine` (testée avec `FakeSource`), réseau dans l'adaptateur mince `YoutubeExplodeSource`. Fait M4A (audio d'origine) et MP4 muxé (360p max) ; MP3 refusé (`formatUnsupported`) faute de ffmpeg. Essai réel : `cd packages/ka7_engine_explode && fvm dart run tool/live_check.dart <dossier>`. État au 2026-10-30 : vidéo seule OK, playlists et chaînes vides (youtube_explode 3.1.0 cassé, dépôt amont inactif depuis mai 2026) ; le moteur les signale en échec au lieu de les rendre vides.
- `packages/ka7_store/` : mémoire locale drift (SQLite) : archive « déjà téléchargé », historique, réglages (clé → valeur), file en cours (`keepPending` / `dropPending` / `pending`, table `pending_downloads`). L'historique garde l'id de playlist (`HistoryItem.playlistId`, null pour une vidéo seule ou une chaîne). « Déjà là » vérifié sur disque : `VerifiedArchive` (archive + `lastPath`, le fichier du dernier téléchargement réussi ; s'il manque, `unarchive` pour ce format, l'historique reste ; sans chemin connu, l'archive fait foi). Branché via `Ka7App.fileExists` (bureau : `File.exists` ; Android : `AndroidMediaStore.existsFor`, méthode `exists` de `MediaStoreChannel.kt`, qui cherche `Music/Ka7/…` dans MediaStore, ou le fichier resté dans le dossier de l'app) et dans le CLI. Abonnements : `follow` / `unfollow` / `subscriptions` (table `subscriptions`, `link` relisible par `parseEntry`). Schéma v6 ; `test/fixtures/schema_v1.sql` à `schema_v5.sql` sont de vraies bases pour tester les migrations. Code généré `lib/src/database.g.dart` : après toute modification des tables, `cd packages/ka7_store && fvm dart run build_runner build`, puis augmenter `schemaVersion` et écrire la migration.
- `cli/` : commande `ka7` (`ka7 links.txt [--format mp3|mp4] [--out dossier] [--jobs 2] [--lang fr|en] [--yes]`, `ka7 retry`). Les mots libres y sont signalés « not a link », comme dans l'app. Pose des questions o/N (chaîne : tout télécharger ? vidéo ouverte depuis une playlist : toute la playlist ?) ; `--yes` répond oui, sans terminal la réponse est non. Barre de progression seulement si la sortie est un terminal (`stdioType`, pas `hasTerminal`, faux sans largeur de fenêtre). Logique testable dans `lib/src/ka7_cli.dart`, branchement réel dans `bin/ka7.dart`. Base partagée avec l'app : `~/.local/share/mg.rakoto.ka7/ka7.sqlite` (Linux). Binaire : `cd cli && fvm dart build cli` (embarque `libsqlite3.so`). Tester Ctrl+C sur le binaire, pas via `fvm dart run`, qui coupe la sortie.
- `app/` : app Flutter, sans logique métier testable sans Flutter (elle va dans `ka7_core`). `Ka7App` (réglages, thème, langue) → `EngineGate` (flux 0 : outils manquants, installation) → `Ka7Shell` (barre latérale, ou onglets sous 720 px ; Ajouter, File, Bibliothèque, Réglages ; tient les files en cours et écrit l'historique). Chaque titre mis en file est gardé dans le store jusqu'à sa fin (réussi, ignoré, échoué, annulé par l'utilisateur) ; fermeture ou plantage le laissent, et au lancement suivant l'app s'ouvre sur File avec la carte « File interrompue » : Reprendre (même format, même dossier) ou Abandonner (annulés dans l'historique). Composants communs dans `lib/widgets/` (`Ka7Page`, `StatusPill`, `Ka7Wordmark`, `Ka7Splash` : écran d'attente au chargement des réglages et pendant `EngineGate` (« Préparation du moteur… »), bobines qui tournent en boucle (`Ka7Logo(loading: true)`) — dans les tests, `pump()` et non `pumpAndSettle()` tant qu'il est affiché ; `Ka7Logo` : cassette de `../ka7-brand/ka7-mark.svg` dessinée en `CustomPainter` aux couleurs du thème, dans la barre latérale et au démarrage). Premier lancement : `OnboardingScreen` (d'abord langue et thème, appliqués tout de suite et enregistrés dans `AppSettings`, puis 4 pages avec points animés, logo aux bobines qui tournent, « Précédent » / « Passer » ; points selon `canDrop` / `canShare` ; animations coupées si le système le demande), avant `EngineGate` ; réglage `onboarding.done`. Les tests d'`app_test.dart` le posent dans `setUp` ; le retirer pour tester la présentation.
- À venir, chacun avec sa première tranche testée : `packages/ka7_engine_explode`.
- Identifiant d'app : `mg.rakoto.ka7` (définitif).
- Formats : `MediaFormat.mp3`, `m4a` (audio d'origine, même dossier que MP3), `mp4`. Bureau et Android proposent MP3, M4A et MP4 ; iOS M4A/MP4 (`Ka7App.formats`, posé dans `main.dart`).
- `app/lib/main.dart` choisit par plateforme : bureau (yt-dlp, `EngineGate`, dossiers par défaut `<Musique XDG>/Ka7` et `<Vidéos XDG>/Ka7` (`ka7Folder`, `platform/user_folders.dart`), comme Music/Ka7 et Movies/Ka7 sur le téléphone ; un dossier choisi dans Réglages prime, `xdg-open`) ou mobile (`ExplodeEngine`, pas d'`EngineGate`, dossiers `Android/data/mg.rakoto.ka7/files/{Music,Movies}` ou `Documents` iOS visibles dans l'app Fichiers, pas d'ouverture de dossier).
- Android : moteur yt-dlp embarqué (youtubedl-android 0.18.1, `android/app/src/main/kotlin/mg/rakoto/ka7/YtDlpChannel.kt`), vu côté Dart comme un processus (`app/lib/platform/android_ytdlp.dart`), donc `YtDlpExtractor` et `YtDlpDownloader` servent tels quels. `AndroidEngineSetup` décompresse le moteur à chaque lancement ; yt-dlp est mis à jour au plus une fois par jour par le même `DailyUpdate` que le bureau (`updateYtDlp`, réglage `ytdlp.updated`, helper `_daily` dans `main.dart`) — le yt-dlp embarqué de nov. 2025 ne lit plus YouTube. Secours automatique : `FallbackExtractor` / `FallbackDownloader` (`ka7_core`) essaient yt-dlp puis youtube_explode, sauf vidéo privée ou indisponible.
- Pages de 16 Ko : le ffmpeg de youtubedl-android ne s'y charge pas (`libwebp` alignée 4 Ko, issue amont #365). `tool/android/fix_ffmpeg_16k.sh` recompile libwebp 1.6.0 avec le NDK et produit `app/android/app/src/main/jniLibs/<abi>/libffmpeg.zip.so` (ignoré par git, environ 100 Mo), qui remplace celui de la bibliothèque (`pickFirsts`). À relancer si la version de youtubedl-android change. L'émulateur `Android_17.0_API_24` est en 16 Ko.
- Qualité (ticket 002) : `Quality` (`ka7_core/lib/src/quality.dart` : `AudioQuality` 128/192/320 kbit/s pour le MP3, `VideoQuality` 480p/720p/1080p/max pour le MP4 ; `Quality.standard` = 192 + 1080p) dans `DownloadRequest` et `DownloadQueue`. yt-dlp : `--audio-quality <kbps>K`, `-f` limité en hauteur avec repli si rien ne rentre (vérifié sur vrai yt-dlp 2026-11-05). M4A : pas de choix (son d'origine). youtube_explode l'ignore (360p muxé). Aperçu : petit menu « 192 kbit/s ▾ » / « 1080p ▾ » à côté du total (`_QualityMenu`), départ = défaut des Réglages (`quality.audio`, `quality.video`, carte Téléchargements). File : une file = format + dossier + qualité ; `pending_downloads` garde la qualité (schéma v6, colonnes `audio_quality`, `video_quality`, nulles avant = défaut) et « Reprendre » relance dans la même. Le CLI reste au défaut.
- Réglages (`AppSettings`, clés du store) : langue, thème (`theme` : `light` / `dark`, absent = système), dossiers, téléchargements simultanés (`downloads.concurrency`, 1 à 4, défaut 2, pour les files suivantes), titres lus dans un mix (`mix.limit`, 25/50/100/200, défaut 50), rangement (`folders.layout` : `artist`, absent = par playlist). Les moteurs lisent la limite au moment de lire (`mixLimit: () => settings.mixLimit`) : `enginesFor(status, settings)`.
- Chaînes dans une recherche : yt-dlp renvoie aussi des chaînes (`ie_key` `YoutubeTab`, `Probe.channels`) et le `channel_id` de chaque vidéo (`ProbeItem.channelId`) ; `channelsMatching(probe, query)` (`ka7_core/lib/src/search_channels.dart`) garde celles dont le nom contient chaque mot de la recherche, sans tenir compte de la casse, chacune une fois. L'aperçu donne à `Ka7Page` un enfant par ligne (`_ProbeGroup.children`, clés par lien et vidéo) : une chaîne de centaines de titres se construit en défilant ; lien suivi `https://www.youtube.com/channel/UC…` (`ChannelRef.link`), le même que `followLinkOf` d'un aperçu de chaîne. - Fichiers sur Android : téléchargés d'abord dans le dossier de l'app, puis déplacés par `PublishingDownloader` (`app/lib/platform/media_store.dart`) et `MediaStoreChannel.kt` dans `Music/Ka7/<playlist>` ou `Movies/Ka7`, visibles par toutes les apps de musique. Android 10+ : MediaStore, sans autorisation ; Android 7 à 9 : dossiers publics avec `WRITE_EXTERNAL_STORAGE` (demandée au début des téléchargements ; refusée, le fichier reste dans le dossier de l'app). Choix du dossier final sur Android : `Ka7App.pickDestination` → `pickAndroidFolder` (`platform/android_folders.dart`, canal `mg.rakoto.ka7/folders`, `FolderPicker.kt` : sélecteur système `ACTION_OPEN_DOCUMENT_TREE`, carte SD comprise, droit d'écriture gardé), réglages `destination.mp3|mp4` (adresse) et `.label` (`SD/Mozika`), `AppSettings.destinationFor` ; carte « Dossiers » des Réglages (« Changer », ↺ « Revenir au dossier par défaut »). Le téléchargement reste dans le dossier de l'app (`pickFolder` null), puis `publishTree` / `existsTree` (`MediaStoreChannel.kt`, androidx DocumentFile) le rangent dans le dossier choisi avec ses sous-dossiers ; sans choix, Music/Ka7 et Movies/Ka7 comme avant. La File affiche le dossier choisi (`Ka7Shell._shownFolder`). Changer de dossier : les anciens fichiers restent où ils sont et ne comptent plus comme « Déjà là ». La File affiche le dossier final (`Ka7App.shownFolder` : `Music/Ka7` ou `Movies/Ka7`), pas le dossier de travail de l'app.
- Signature : clé de publication `~/.config/ka7/ka7-release.jks` (alias `ka7`, RSA 4096, valable 100 ans), mot de passe dans `~/.config/ka7/key.properties`, lu directement par Gradle (autre chemin : variable `KA7_KEY_PROPERTIES`) ; rien dans le projet. Perdre la clé empêche toute mise à jour chez ceux qui ont installé l'app : la sauvegarder hors de cette machine. Sans ce fichier, la release est signée avec la clé de debug.
- Icônes : `tool/render_icons.py` (`cd app && uv run --with cairosvg python -I ../tool/render_icons.py`) produit `app/assets/icon/` depuis `../ka7-brand/`, puis `cd app && fvm dart run flutter_launcher_icons` (réglages dans `app/pubspec.yaml`) génère Android (adaptative + monochrome), iOS, Windows et macOS. Linux : icônes de `packaging/linux/`.
- Paquets Android : `tool/package_android.sh` → `dist/Ka7-<version>-{arm64-v8a,armeabi-v7a,x86_64}.apk` (environ 55 à 65 Mo chacun, contre 257 Mo en debug universel). Signés avec la clé de publication (voir Signature). Numéro interne : `--split-per-abi` ajoute 1000 × ABI au numéro de build (x86_64 : 4001 pour `0.1.0+1`). Un APK non découpé porte le numéro de build seul (1) et ne peut pas mettre à jour une installation faite depuis `dist/` (`INSTALL_FAILED_VERSION_DOWNGRADE`) : pour essayer une mise à jour, `fvm flutter build apk --release --split-per-abi --target-platform android-x64`. À chaque version publiée, augmenter aussi le `+N` de `app/pubspec.yaml`.
- Java : Flutter utilise le JDK d'Android Studio (`fvm flutter config --jdk-dir=/snap/android-studio/current/jbr`), la Java du système n'a pas `javac`.
- Android : `fvm flutter build apk --debug` depuis `app/` ; émulateur `Android_17.0_API_24` (API 37, x86_64) : `~/Android/Sdk/emulator/emulator -avd Android_17.0_API_24 -no-window`. iOS : pas de build possible sous Linux (Xcode requis).
- Nouveau paquet : l'ajouter à `workspace:` dans `pubspec.yaml` et mettre `resolution: workspace` dans le sien.

## Nouvelle version

- Au lancement, au plus une fois par jour, Ka7 demande à GitHub la dernière release (`fetchLatestRelease`, `ka7_core/lib/src/app_release.dart`, API `repos/jmRakoto/ka7/releases/latest`) ; si elle est plus récente (`isNewer`), carte « Ka7 x.y.z est disponible » en haut d'Ajouter, « Télécharger la mise à jour » ouvre la page de release (bureau : `xdg-open` ; Android : canal `mg.rakoto.ka7/open` dans `MainActivity.kt`), ✕ la remet à la version suivante. Réglages `update.checked`, `update.latest`, `update.url`, `update.dismissed`.
- Version de l'app : `--dart-define=KA7_VERSION=<version>`, passé par `tool/package_linux.sh` et `tool/package_android.sh` (Flutter ne fournit `FLUTTER_BUILD_NAME` qu'à iOS et Windows). Absente avec `flutter run` : pas de vérification en développement.
- `tool/release.sh [--dry-run] notes.md` publie une version (voir README).
- `app/integration_test/` : attendre la fin de l'apparition d'une page (`pump(600 ms)`) avant de taper ou toucher, sinon la saisie se perd.

## Rendu et paquets

- Windows : Flutter ne construit pas pour Windows depuis Linux. `.github/workflows/windows.yml` (GitHub Actions, `windows-latest`, Flutter 3.44.4 comme ici) part à chaque release publiée : `flutter build windows`, zip `Ka7-<version>-windows-x64.zip`, installateur Inno Setup `Ka7-<version>-windows-setup.exe` (`packaging/windows/ka7.iss`, par utilisateur sans droits admin, `AppId` à ne jamais changer), ajoutés à la release avec la partie « Windows » des notes et leurs SHA-256. À la main : Actions → Windows → Run workflow (artefact téléchargeable ; « upload » sur une étiquette = ajout à sa release). Non signé : SmartScreen avertit. Jamais essayé sur un vrai PC Windows au 2026-11-05.
- Code Windows : `EngineBinaries(windows: true)` (`yt-dlp.exe`, ffmpeg en zip LGPL win64 extrait par le `tar` de Windows, `where` au lieu de `which`, pas de `chmod`) ; `openOnDesktop` (`platform/desktop_open.dart` : `xdg-open` ou `explorer`, barres inverses pour les dossiers) ; `userFolder(windows: true)` demande à PowerShell `[Environment]::GetFolderPath('MyMusic'|'MyVideos')` (suit OneDrive), repli `%USERPROFILE%\Music` ; pas de notification de fin sous Windows. Icône `app/windows/runner/resources/app_icon.ico` de 16 à 256 px.

- Captures de tous les écrans (bureau et téléphone, clair et sombre, vraies polices) : `cd app && KA7_SHOTS=/dossier fvm flutter test tool/screenshots/screenshots_test.dart`. À regarder après tout travail d'interface.
- Paquets Linux reproductibles : même commit → mêmes fichiers. `SOURCE_DATE_EPOCH` = date du dernier commit, toutes les dates des paquets ramenées dessus, et le dossier `bundle` de Flutter vidé avant chaque construction (des restes d'anciennes constructions y traînaient : `native_assets.json` avec un chemin local, icônes Cupertino).
- Paquets Linux : `tool/package_linux.sh` → `dist/ka7_<version>_amd64.deb` (app `ka7-app` + CLI `ka7`) et `dist/Ka7-<version>-x86_64.AppImage` (app seule). Icônes et `.desktop` dans `packaging/linux/` (copies de `../ka7-brand/`). Version lue dans `app/pubspec.yaml`.
